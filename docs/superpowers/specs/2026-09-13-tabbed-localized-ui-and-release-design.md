# FrameCompare v2 分页、本地化与自动发布设计

## 状态

- 日期：2026-09-13
- UI 分页方案已由用户确认。
- 发布方式已选择语义版本标签发布。
- 用户新增要求：界面可切换简体中文和英文，默认简体中文。
- 用户已书面确认本设计，实施按对应计划执行。

## 目标

在不改变现有对比、扫屏、标签、快捷键、状态提示和配置行为的前提下：

1. 把当前纵向连续展开的面板改为顶部分页切换。
2. 消除每个控件同时显示中文和英文造成的冗长界面。
3. 提供可持久化的简体中文/英文界面选择，默认简体中文。
4. 让 GitHub Actions 同时验证并打包 32 位与 64 位 add-on。
5. 仅在推送语义版本标签后自动发布正式 GitHub Release。
6. 发布 `v2.0.0`，作为接入 DLSS5 之前的固定稳定备份。

## 不在本次范围内

- 不接入 DLSS5、NGX hook 或新的捕获来源。
- 不改变 Before/After 捕获语义。
- 不改变默认快捷键、扫屏逻辑、标签裁切或 HUD 状态判断。
- 不把当前页签写入 INI；每次加载默认进入“对比”页。
- 不自动翻译用户填写的 ON/OFF 文字或状态条目名称。
- 不删除 `archive/v1.3-complete` 或 `v2-development` 分支。

## 方案选择

### 已选：顶部页签

使用 ImGui `BeginTabBar`/`BeginTabItem` 实现六个互斥页面。顶部页签始终可见，
活动页使用 ReShade 当前主题的选中颜色。面板较窄时允许 ImGui 显示页签滚动按钮，
避免文字被裁切。

页签名称保持简短：

1. 对比 / Compare
2. 扫屏 / Motion
3. 快捷键 / Hotkeys
4. 标签 / Labels
5. 状态 / Status
6. 配置 / Config

只有活动页绘制内容。切换页签不修改任何功能设置，也不触发捕获重置。

### 未选方案

- 折叠标题：可以缩短面板，但查找不同功能仍需要上下滚动。
- 单一手写按钮组：外观接近参考截图，但需要自行维护选中状态、宽度和键盘导航；
  ImGui 原生页签已经提供这些行为。

### 快捷键

- 当前全部九项快捷键绑定
- 清除单项绑定
- 恢复默认快捷键

### 标签

- 显示标签
- Before/After 自定义文字
- 左右标签位置

### 状态

## 本地化架构

### 权威状态

新增 `UiLanguage`，仅有 `zh_cn` 和 `en`。一个 UI 本地化运行态持有当前语言，
默认 `zh_cn`。所有面板、按钮、提示和配置状态通过稳定 `TextId` 查询文本，
不再在调用位置硬编码双语字符串。

本地化模块放在 `src/ui/i18n/`，避免 `src/ui` 超过八个直属文件：

- `localization.hpp`：`UiLanguage`、`TextId`、查询和解析接口。
- `localization.cpp`：完整中文表、英文表、默认值和缺失键保护。

若某个键意外缺失，显示稳定键名并由测试失败，不能退回双语拼接。

### 稳定 ImGui ID

可交互控件使用 `本地化文字##stable_id`。切换语言只改变可见文本，不改变
隐藏 ID，避免输入框失焦、树节点状态错位或快捷键捕获中断。

用户数据不经过本地化：

- Before/After 默认内容仍为 `OFF`/`ON`。
- 已保存的状态名称与 ON/OFF 文字保持原样。
- 键名如 `Ctrl`、`F7`、`CapsLock` 保持标准键名。

### 配置兼容

`FrameCompare.ini` 新增：

```ini
[UI]
Language=zh-CN
```

- 旧 INI 没有该字段时使用简体中文。
- 支持值为 `zh-CN` 和 `en`。
- 未知或损坏值回退简体中文。
- 保存与重新加载继续使用现有 0.75 秒防抖和手动按钮。
- 语言设置与其他配置一起编码，不新建第二份配置文件。

配置运行态当前保存双语状态字符串。实施时改为稳定状态枚举，UI 按当前语言显示，
避免保存成功、读取失败等消息继续混合双语。

## UI 模块边界

`src/ui/panel.cpp` 只负责顶部语言选择、页签协调和调用页面函数。
页面内容移动到 `src/ui/pages/panel_pages.hpp/.cpp`，保持一个明确的“设置页面绘制”
职责。现有 `hud::draw_indicator_panel` 继续负责状态条目正文，由“状态”页调用。

`parameter_widgets` 和 `input/hotkeys` 中的“重置、清除、未设置、请按键”等内部
文字改为通过本地化模块查询。所有可变设置仍由原来的 render、motion、hotkey、
label、indicator 和 config 模块持有；UI 不创建重复状态副本。

## 32 位和 64 位构建

官方 ReShade 同时加载 `.addon32` 与 `.addon64`，官方示例也提供 Win32/x64 配置。
FrameCompare 当前业务代码使用 ReShade 抽象资源句柄和 `std::uintptr_t`，没有发现
必须为 64 位的第一方类型。

CMake 根据 `CMAKE_SIZEOF_VOID_P` 选择：

- 64 位：`00-FrameCompare-v2.addon64`
- 32 位：`00-FrameCompare-v2.addon32`

每个架构使用独立构建目录和独立 package 目录。32 位能否交付的权威证据是
GitHub Windows/MSVC Win32 构建与测试通过；静态判断不替代编译，更不替代具体
32 位游戏中的运行验证。

## GitHub Actions 与 Release

### 普通持续集成

- `main` push、pull request 和手动运行继续执行静态审计。
- 使用 `x64` 与 `Win32` 矩阵分别配置、构建并运行全部测试。
- 分别上传临时 Actions 制品，便于测试未发布提交。
- 普通提交绝不创建或覆盖 GitHub Release。

### 标签发布

匹配 `v*.*.*` 的标签触发同一双架构验证。Release job 必须依赖两个矩阵构建，
只有全部成功才运行。

Release job：

1. 下载两个 package 制品。
2. 分别生成：
   - `FrameCompare-v2.0.0-windows-x64.zip`
   - `FrameCompare-v2.0.0-windows-x86.zip`
3. 生成两个 ZIP 的 SHA-256 校验文件。
4. 使用 runner 自带的 GitHub CLI 和当前仓库 `GITHUB_TOKEN` 创建正式 Release。
5. Release job 单独声明 `contents: write`；构建 job 仅需 `contents: read`。
6. 若相同标签已有 Release，流程失败并保留旧 Release，不覆盖固定备份。

初次发布顺序：先把本次代码推送到 `main`，确认 Win32/x64 普通 CI 都通过；
随后创建并推送 `v2.0.0` 标签。标签工作流再次从该精确提交构建，成功后自动发布。
这保证 Release 二进制来自标签提交，而不是从之前某次临时制品手工搬运。

## 失败处理

- 任一架构编译或测试失败：不创建 Release，修复后重新运行普通 CI。
- 标签工作流失败：保留标签和日志，不覆盖已有 Release；修复后使用新的补丁版本标签。
- 本地化键缺失：测试失败，不以中英双语拼接掩盖。
- 旧 INI 读取异常语言：回退简体中文，其余配置继续加载。
